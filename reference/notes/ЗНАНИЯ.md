# Знания: как редактировать карты WC3 1.26a скриптами

## Инструменты
- **StormLib** (`wc3-td\build\tools\StormLib.dll`) через ctypes в `make_base.py`: `open_archive`, `read`, `write_files`. Пути Unicode, кириллица работает.
- **pjass** (`wc3-td\build\tools\pjass.exe`) + `gamedata\common.j`, `Blizzard.j`: проверка JASS. Не понимает кириллицу в пути, поэтому копируем файлы во временную папку.
- **cfobj.py**: читает и пишет w3u/w3a/w3t без потерь (поле: id, тип, уровень, данные, значение, 4 байта конца). `parse(data, levels)`; для w3a levels=True.
- **mpqcopy\**: копии War3Patch/war3/War3x.mpq. Оригинальные MPQ заблокированы, пока war3 запущен.
- Названия объектов лежат в `war3map.wts` (`TRIGSTR_NNN`), не в w3u.

## Устройство файлов карты
- `war3map.j`: скрипт. В Castle Fight имена обфусцированы (`n`, `L`, `rc`, `a`...).
- `war3map.w3u/w3a/w3t`: юниты, способности, предметы. Стандартные значения в SLK из MPQ (`Units\AbilityData.slk` и т.д.).
- `war3map.w3e`: ландшафт. Заголовок: `W3E!`, версия(4), тайлсет(1), custom(4), число текстур(4) с байта 13, текстуры по 4 байта с 17, клифы, размер, угол; точка 7 байт, текстура = младшие 4 бита байта 4. Сетка снизу вверх.
- `war3map.wpm`: проходимость, клетка 32x32 (4 на тайл), строки снизу вверх. Флаги: 0x02 нельзя ходить, 0x04 нельзя летать, 0x08 нельзя строить, 0x40 обычная земля.
- `war3mapSkin.txt` `[Errors]`: тексты ошибок. Значение = 4 текста через запятую (по расе), иначе «Error message missing».

## Грабли (каждая стоила вылета или незагрузки)
- **Вылет ACCESS_VIOLATION 0x24** = сломанный объект, не скрипт. Способность на основе `AIde` (её нет в 1.26, это только код для `AId1..5`). Сборка проверяет, что основа каждой своей способности есть в AbilityData.slk.
- **Книга заклинаний (Aspb)** в ячейке, занятой родной кнопкой, роняла игру. Кнопки ставить прямо на юнит в свободные ячейки.
- **Карта молча не грузится (возврат в меню)**, если имя локальной переменной или параметра совпадает с именем функции карты (или типом JASS, `race`). В CF все мои локали с префиксом `cf_`, в сборке assert.
- В лобби 1.26: правка имени карты в w3i ломала лобби.
- Строковый литерал JASS не длиннее 1023 байт (кириллица = 2 байта).
- Апостроф в JASS-комментарии ломает разбор rawcode в gen.py.
- Функцию объявлять выше места вызова.
- Типы attackBits, bool, channelType, channelFlags в w3u/w3a хранить как int.
- Способ стройки зависит от расы строителя: орки и эльфы прячут строителя внутрь (TD: герои urac=undead).
- **Channel по точке не кастуется с приказом `innerfire`** (его движок принимает только с целью-юнитом): умения молча не работали. Для точки брать `blizzard`. Проверять кастом через `IssuePointOrder` в автотесте, а не прямым вызовом функции эффекта.
- Невидимость `Apiv`, выданная триггером, не прячет юнита в бою (враг его видит). Для «по нам не попадают» надёжнее уклонение `AIev` (поле `Eev1`).
- Оружие `artillery` стреляет в точку на земле, бегущий юнит уходит из-под удара; `msplash` летит за целью и сохраняет сплэш.
- war3 не закрывается taskkill. Работает Alt+F4 и X через `keybd_event` (`castle-fight\_close.ps1`); SendKeys и клики мышью игра принимает ненадёжно (экран 125%, курсор игры отстаёт).

## Castle Fight: анатомия оригинала
- Доход: таймер `ko`, период `Mo`, `PF` -> `ForForce(Ba, pF)`; `yx` стоимость зданий, `Kx` сундуки.
- Замок раунда: `Rr[0]` / `Rr[1]` (пересоздаётся каждый раунд). `fE`/`FE` стартовые, не использовать.
- Команда игрока: `Fi[pid+1]`; силы команд `wo[t]`.
- Боты: `se[pid+1]=true` (функция `ZR`), и слот «Компьютер», и `-east/-west/-fill`. Боты строят в случайные точки зон (`Ox/Ex/Xx`), 15 попыток.
- Линии: верхняя `xn` (центр 0,832), нижняя `on` (0,-832). `io` = закрытая линия в режиме одной линии (0 верх, 1 низ, -1 обе открыты).
- Дороги: текстуры `Vstp` и `Zdtr`.
- Легендарные здания занимают 1 еду; еду продаёт замок: предмет «Сыр» `I004` за 1500 золота.
- Парсер режимов: `Bd` / `fd`. Строитель: занятые ячейки 0,0 1,0 2,0 0,1 1,1 0,2 1,2 3,2; свободные 2,1 3,1 2,2 3,0.
- В оригинале был бэкдор (читы по никам JJ2197 / FatherSpace), вырезан в сборке.

## Порядок работы, который сработал
1. Разобраться логически, найти закономерность по логам, потом одна надёжная сборка.
2. Каждый новый объект проверять автотестом (шаги в `build_cf.py`, лог через Preload).
3. Перед релизом: тест до `FINISH`, затем релиз, старая версия в `_old_tests`.
- Грабля (2026-11-15): флаг 0x08 (нельзя строить) в war3map.wpm на клетках под зданием, созданным через CreateUnit, сдвигает здание на ближайшее допустимое место. Площадку замков (±4864, 0) из запрета на дорогах исключать (build_cf.py).

## Уроки v12-v16 (2026-11-18)
- **Невидимый юнит = нет модели.** Путь модели в w3u (`umdl` .mdl) должен существовать в MPQ как `.mdx`. Неверный путь: юнит живёт, бьёт и бьётся, но не рисуется. У боссов были неверны 5 путей (Paladin, Lich, Dreadlord, creeps\Illidan, HeroBloodElfPrince). Верные: `units\human\Uther\Uther`, `units\human\Kael\Kael`, `units\undead\Kelthuzad\Kelthuzad`, `units\undead\HeroDreadLord\HeroDreadLord`, `units\nightelf\HeroDemonHunter\HeroDemonHunter`. Проверять через StormLib `SFileHasFile` по mpqcopy (restype c_bool!), сборка теперь делает это сама.
- **Боты одной команды и разовые умения:** нужна блокировка на команду (`CF_StrikeT[Fi[p+1]]`, время по `CF_BT`), иначе в одном тике жмут все. Шаг ботов 3 с, поэтому задержки меньше 3 с фактически равны 3 с.
- **Кнопка «только следующий шаг»:** многоуровневый Channel (ANcl) на строителе работает в 1.26a; уровень кнопки = купленный уровень + 1, `SetUnitAbilityLevel` при покупке и раз в 2 с (новый строитель в новом раунде). `gen.channel` пишет заголовок «(рівень N)», заменяем строкой (строки в w3a нуль-терминированы, длину менять можно).
- **Процентный бонус урона:** процентной предметной способности нет. Считаем средний урон удара бойца при сборке (`ua1b + ua1d*(ua1s+1)/2`), кладём в hashtable (`SaveInteger(CF_HD,0,тип,урон)`), выдаём одноуровневую AIat на нужное число (`Cw01..Cw99`, `Cx00..`). Броня: AId1-5, AId7 (+6 = AId5+AId1; AId6 нет).
- **Начало раунда** в оригинале: строка `set Rr[i]=bj_lastCreatedUnit` (создание замка раунда), туда патчим сброс кузницы и часов ботов.
- **Экономика CF:** доход за тик = 10*(0.5 + 0.002*V)*CF_M с убывающей отдачей (ступени 25), V = стоимость зданий (ro=0.2 * cost / 100). Модель: `castle-fight\_econ.py`, `_econ2.py`.
- **Автотест союзников:** в тестовой игре слот 7 пустой (`GetPlayerSlotState` не PLAYING); сборка `testf2` снимает эту проверку только в тесте.
- Локальные имена в моём JASS не должны совпадать с глобалами карты (`ma`, `md`, `me`, `q` заняты): префикс `cf_`.

## Уроки BvO этапы 7-9 (2026-11-19)
- **Dialog в одиночной игре ставит игру на паузу** (таймеры стоят). Автотест с открытым окном замирает: в тестовой сборке окно не показывать, отвечать скриптом.
- **Группа перезарядки предмета наследуется от основы** (`cooldownID` в ItemData.slk, поле `icid` в w3t, тип 3 строка). У `stwp` это `AItp`: все предметы на его основе делят перезарядку между собой и со свитком телепорта. Для своих активных предметов ставить `icid` = своя способность.
- `UnitUseItemPoint` может вернуть false, хотя каст прошёл: не опираться на его ответ.
- **war3 исчез без Crash.txt** в `Errors\` = игру закрыли (Alt+F4 + X), а не вылет: настоящий вылет 1.26a пишет Crash.txt. Два чата с автотестами war3 мешают друг другу: `_close.ps1` бьёт по активному окну игры. Запуск только при свободном war3, следить за своим pid (`bleach-op\_runtest.ps1`, `_suite.ps1 -waitfree`).
- Урон `ATTACK_TYPE_NORMAL` (умения) по героям = 75%.
- Оригинальный ИИ BvO включается при старте, только если в лобби есть слоты Computer (`mH`); автотест через `-loadfile` его не включает.

## Как работать без лишних кругов: мои ошибки и правила (2026-11-19, BvO этапы 7-9)
Каждая строка стоила лишнего прогона, перечитывания или неверного отчёта владельцу.
1. **«Закрыто» не значит «прошло».** Я доложил «w1 и b2 отработали», а w1 вылетела при загрузке, b2 через 3 с. Тест считается пройденным только по строке `state=FINISH` раннера и строке `FINISH` в логе. Перед отчётом прогнать `_logsum.py <карта> -full` и назвать, что проверено, а что нет.
2. **Нет Crash.txt, значит игру закрыли, а не карта упала.** Сначала смотреть `Errors\` и соседние чаты (`list_sessions`, свежие файлы в `Maps\cf_test`, `Logs\cftest.txt`), потом искать ошибку в коде. Так не тратится час на поиск несуществующего бага.
3. **Один war3 на весь компьютер.** Другие чаты проекта тоже запускают игру. Тесты только через `_suite.ps1 -waitfree` (ждёт минуту тишины), свой pid в логе. Если запуск блокирует защита разрешений, не обходить, а ждать или спросить владельца.
4. **Тест ускоряет игровое время (x20), а бой идёт в реальном.** Таймеры волн и окон по `bx_Sec` в тесте истекают за секунды: бот «не успевает» не из-за ошибки. Бой и походы проверять на шагах с запасом реального времени или ставить юнитов рядом.
5. **Порядок внутри тика.** Тест логирует до шага модуля в том же тике, поэтому результат команды читать на следующем тике.
6. **Место теста.** Не ставить героев у вражеской базы (башни и фонтан убивают сразу). Нейтральные точки: святилища (x 1050 или -2400, y 1300 или -1300).
7. **Модальные окна.** Dialog в одиночной игре ставит паузу, автотест замирает. В T-сборке окна не показывать, вид окна проверять одним снимком.
8. **Межмодульные вызовы.** Модуль вызывает только core и объявленные зависимости (`build_bvo.py`, список пар). Общие помощники (`bx_B2S`) держать в core. Тестовый код тоже: в perks была ссылка на функцию из bot.
9. **Счётчики по общему накоплению** (урон боссу, убийства) брать с базой на момент выдачи задачи и сбрасывать при смене события (новый босс).
10. **Объекты от основы** наследуют скрытые поля (группа перезарядки, классы). Перед новым активным предметом или способностью сверить поля основы в SLK (`build\game\*.slk`), а не догадываться.
11. **Экономия контекста.** Большие модули (bot.j 800+ строк) не перечитывать целиком: Grep по имени функции, Read с offset. Логи только через `_logsum.py`, снимок окна один на проверку. Python с бэкслешами только файлом через Write: heredoc ломает `\U` и рвёт запуск.
12. **Один чат = один этап.** Этапы 7-9 в одном чате довели контекст до сжатия, и в сжатом пересказе ошибка из п. 1 пережила сжатие как «пройдено». Закрывать этап сразу после проверки и переходить в новый чат.

## Уроки BvO этап 10 (2026-11-19)
- **Таймаут без FINISH не равен ошибке карты.** Тесты w2 и p2 упёрлись в лимит 150 с на игровой секунде 1200 из 1300: игра идёт медленнее, пока окно war3 не на переднем плане (владелец работает в другом окне). Перезапуск с `-wait 220` дал FINISH за 91-107 с. Лимит ставить 220 с и сначала смотреть, на какой секунде оборвался лог.
- **Окно «Выход из игры» после FINISH.** Если фокус у другого окна, `_close.ps1` не закрывает игру: Alt+F4 только переключает диалог, клавиша X уходит чужому окну, `SetForegroundWindow` блокируется. Рабочий выход: попросить владельца нажать «Выйти». Не повторять `_close` по кругу.
- **`-loadfile` не создаёт компьютерных игроков.** Слоты Computer в `war3map.w3i` (тип 2) игнорируются, `SetPlayerSlotState` в 1.26a нет (есть только `GetPlayerSlotState`). Оригинальная проверка `mH()` смотрит только на контроллер, поэтому `BX_COMPUTERS=1,6,7` (только тестовая сборка) вставляет `SetPlayerController(...COMPUTER)` в начало `main`: Ps, покупки при смерти и выбор умений оригинала работают на героях тестовых ботов. Так проверены `-classic` (Ps включается и выключается) и каст умения ботом. Вставка внутри `bx_bot_Init` опоздала: оригинальный старт уже выполнился.
- **Меню war3 из скриптов.** Окно `-window` на этом ноутбуке обрезано (реестр 800x600, окно 1152x592), кнопки меню видны наполовину; клики `mouse_event` по меню не сработали, `keybd_event` с окна работает и в меню, и в чате игры. Computer-use не видит war3 (его нет в списке приложений). Пройти лобби и поставить Computer автоматом не удалось: это проверяет владелец в первой партии.
- **Проба живой партии.** `BX_PROBE=1` в сборке (не T): в `Logs\bvo_<имя>.txt` раз в минуту пишутся строки `ECO` по каждому герою (уровень, золото, медали, предметы, убийства, смерти, пометка U человек или C компьютер), на 30-й секунде минуты `BOTP` по каждому боту, плюс смены фаз ботов. Проверено тестом `pb` (ECO на t=1200, BOTP на t=600). Если владелец играет с ботами, такая сборка даёт лог для калибровки без ручных замеров.
- **Баланс золота.** Награды мира (контракты, боссы, додзё, разлом, святилище Золота) по расчёту дают около 13 700 золота на героя за 30 минут против 10 200 пассивного дохода без крипов (раздел 2.6 ДИЗАЙН.md). Контракт «Покупатель» окупался с прибылью: цель стала 2 покупки.
- **Боты без лобби (2026-11-19).** Слот, которому на 2-й секунде выставили `SetPlayerController(...COMPUTER)`, получает от оригинала героя, дерётся и кастует. Условия: (1) на старте оригинала (`mH()` в начале `main`) должен быть хотя бы один Computer, иначе оригинал УНИЧТОЖАЕТ свои компьютерные триггеры (патруль, покупки, умения), поэтому `build_bvo.py` ставит «фантомный» Computer на старший пустой слот и модуль bot на 2-й секунде возвращает ему `MAP_CONTROL_USER`; (2) бота надо вписать в силы оригинала `ForceAddPlayer(udg_e или udg_f, ...)` и в группу дохода `udg_M9` (иначе золото не идёт); (3) пересчитать лимит убийств `udg_k` по формуле оригинала: `((число в e + число в f)/2)*60`, минус 30, если не 0. Без этого у одного человека лимит 0 и «Team Wins» срабатывает на первом засчитанном убийстве (партия заканчивалась на 47-й секунде экраном LOSER).
- **Оригинал заканчивает партию, когда команда набрала `udg_k` очков** (триггеры `udg_Dt` и `udg_Et`, условие `udg_h >= udg_k`); тесты с ботами раньше не видели этого, потому что боты вне сил не засчитывались.
- **Команды ботов:** `-addbots [N] [easy|normal|hard|insane]` (противники), `-addallies` (союзники), только хозяин, первые 25 секунд; у каждого бота своя сложность (hash i,45). Настоящие Computer из лобби берут сложность из слота (Easy, Normal, Insane).
- **Длинный живой прогон** (`_live_retry.ps1`: `BX_PROBE=1 BX_AUTOCMD="-addbots 3 hard|-addallies 1 normal" BX_GOD=1 BX_FASTSPEED=1`) пишет память war3 раз в минуту в `build\mem_<имя>.txt`. Прогон lr2 в счёт не идёт: игра стояла на экране LOSER.
- **Python в heredoc снова испортил `\n`** (правка `build_bvo.py`): сразу видно по `SyntaxError: unterminated string literal`. Правки с `\n` в строках только через Edit или Write.

## Предметы замка v24 (2026-11-19, задача cf-items-race)
- Новые предметы: w3t читается и пишется в build_cf.py (`ttabs[1].append(C.Obj('sres', 'I00E', [...]))`), продажа через `umki` у `hcas` (замок «делает» предметы) и `usei` у торговца `n00U`. ID умений предметов Ci*, префикс Cw занят кузницей.
- Предмет без цели = канал `ANcl` (`gen.channel(..., ttype=0, ...)`) в `iabi`/`icid`; событие SPELL_EFFECT даёт `GetTriggerUnit` = строитель, дальше обычная ветка `CF_OnSpell`. Расходуется сам (база sres: uses 1).
- Отрицательная скорость атаки: одноуровневая `AIsx` с `Isx1 = -0.4` работает в 1.26 (атак 7 -> 4 за 10 с). Бег: `SetUnitMoveSpeed(default*.75)` + возврат таймером. Неуязвимость зданий: `SetUnitInvulnerable` (в игре = умение `Avul`), снимает `CF_Timed` с k=3.
- Тест (режим testi): событие ATTACKED игрока срабатывает, когда бьют ЕГО юнитов (счётчик CF_AA); строитель, созданный в тесте, сам уходит с места: телепортировать перед применением; раунд стартует примерно на 5-м шаге (CF_T начинает идти).

## Раса «Сборщики»: как устроена раса в CF (2026-11-19, этап 3 задачи cf-items-race)
- Код расы: `castle-fight\race_sbor.py` (данные, клонирование объектов, правки скрипта, тексты RU+UA). В `build_cf.py` только 4 вставки (импорт, добавление ДО баланса, `RS.finalize_text` ПОСЛЕ баланса, строка в `RACES`/`SKILL`) и ветка теста `tests`.
- Раса = строитель (`ubui` = список зданий, `upoi` = индекс расы, `ubpx/ubpy` = кнопка в магазине рас 4 на 3; свободно было только (2,2) и (3,2)). В скрипте: `Yr` (последний индекс расы), `ti[i]` (строитель), `Go[i]` (родительный падеж для сообщений). «Стабильный мод» делает `Yr=Yr-1`, то есть отключает последнюю по номеру расу (сейчас Сборщиков).
- Здание регистрируется в функции с `set vC=<раса>`: `Wc(здание, цена, боец, класс_атаки, класс_брони, vC, приоритет)`, `oC` осада, `EC(улучшение, доплата, боец, цена_прошлого, прошлое, ...)`, `VC(башня, цена, vC, 300)`. Классы нужны только ИИ ботов (подбор контр-бойцов), на бой не влияют: атака dC=0 обычная, DC=1 колющая, fC=2 осадная, FC=3 магия, gC=4 хаос; броня NC=0 лёгкая, bC=1 средняя, BC=2 тяжёлая, cC=3 крепость, CC=4 герой (по коду `Gc`, у оригинала встречаются расхождения). Приоритет по коду бота: 1 бьёт только воздух, 2 только землю, 3 оба. Индексы массивов = point value (`upoi`) здания: должны быть уникальны (свободно с 152; 1000+ служебные).
- Боец появляется так: построенное здание получает `IssueImmediateOrderById(здание, id_бойца)`: то есть здание ТРЕНИРУЕТ бойца (`utra` = id бойца, время тренировки = `ubld` самого бойца, цена бойца 0). Клонируйте существующего бойца-аналога: у всех бойцов `utyp = sapper,ward` (скрипт узнаёт бойцов по классу SAPPER).
- Тиры зданий: `ureq` `tec1/tec2/tec3` + `urqa 1`; по цене: без требований до 220, tec1 примерно 200-280 и дешёвые улучшения, tec2 улучшения и базовые 290-375, tec3 дорогие. Способность `A07E` у здания = «владеет юнитами-декорациями» (скрипт чистит их при гибели): у клонов её убирать.
- Аналоги: у каждой расы по 3-4 «особых» здания (`rC`, id в `ubui`), у Сборщиков их пока нет: только 6 основных, 3 улучшения, сундук `h008` и башня `cg0a` (клон `h006`).
- ID в `build_cf.py`: строчная первая буква у юнитов и зданий (`cg*`), у умений и баффов `Cg*`/`Cr*`.
- Модели из игры проверять `mb.read(arc, путь.mdx)` по `castle-fight\mpqcopy` (сборка делает это сама для Сборщиков). Нет в игре: `units\creeps\Sentinel`, `units\creeps\Golem`, `units\creeps\Mercenary`.
