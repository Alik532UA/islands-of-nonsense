## 1. Правки кода
- Большие скрипты (`build_cf.py`, `bot_ai.py`, модули) правлю только инструментом Edit, несколько мест одним сообщением. Python-heredoc с `\n` и кавычками портил строки три раза за день (реальный перенос строки внутри строки Python). Если нужна массовая замена: Write в `_имя.py` и запуск файла.
- После каждой правки Python-файла сразу `python -X utf8 -m py_compile build_cf.py` (1 секунда), не ждать полной сборки на 40 секунд.
- JASS в моих модулях:
  - локальные переменные и параметры с префиксом `cf_`: короткие имена (`a`, `n`) совпадают с именами карты, сборка падает;
  - функция должна быть объявлена выше места вызова. Общие функции класть в `RSJ.FUNCS` (перед `QC`) или в `CF_FUNCS`; тестовые помощники в `TEST_FUNCS` (после `CF_Log`, до `CF_Castle`); `CF_SbCnt` есть только в ветках `tests*`;
  - замок текущего раунда это `Rr[team]` (через `CF_Castle`), а не `fE`/`FE`;
  - метки `//CMDLOG_*`, `//SPLOG_*` дают лог только в тестовых сборках, в релизе очищаются (проверять, что очистка есть для каждой новой метки);
  - события смерти не вызывает `RemoveUnit`: счётчики зданий обнулять в начале раунда;
  - свои ID: Grep по `build_cf.py` и `race_sbor.py` на занятость, потом `assert`.
- Любой текст для игрока (имя, подсказка, сообщение) сразу проверить в UA: строка берётся по точному совпадению из `_new_ua.py` / `race_sbor_ua.json`; после правки текста обновить перевод и прогнать скан (`_scan_map.py`, `_probe_j.py`).
- Файл спеки, плана, состояния: перед перезаписью копия `*_vN.md` или `.bak-ДАТА` (я потерял спеку v4 командиров).

## 2. Тесты: как не мерить пустоту
- Первая строка теста пишет предусловия: раса игроков (`ui`), враги ли стороны (`IsUnitEnemy`), реальное здоровье и положение. Если числа одинаковы при разных условиях (`lost=88835` во всех четырёх попытках), измерения нет: сначала чинить измерение.
- Для любого эффекта нужен контроль («без командира») и измеренная величина, а не наличие способности. Наличие способности не равно эффекту: Дима и Дэн сначала были проверены только по наличию.
- Расу игроков в тестовой карте нельзя «ожидать»: случайный выбор детерминирован, у игрока 0 выпали Ночные эльфы. Нужна конкретная раса: форсировать (`patch('return eA[...]', 'return 10')`).
- Тестовая функция не больше ~30 веток; пустые шаги без веток (160 веток роняли игру при загрузке).
- Раунд в тестовой карте обрывается примерно на 160 секунде сам, без причины: длинную партию и процент побед тестами не измерить. Не планировать 15-минутные прогоны; баланс по расчёту и по партиям владельца.
- Лог копировать в `out\` сразу и проверять свежесть (время файла и метка первой строки). Читать старый лог за новый случалось дважды.
- «Прошло» только по `FINISH`; без него писать «не завершён» и причину (таймаут окна, не вылет).
- Вылет без единой строки лога: сначала бисекция самого теста (пустые шаги, половина шагов), и только потом объекты. Я потратил много запусков на гипотезы про строителя, а причиной был размер тестовой функции.

## 3. Запуск игры
- war3 один на компьютер; без фокуса игра стоит (замер: 3 тика за 7 минут). Режим `-quiet` не использовать. Окно в углу: `_run_when_free.ps1 -small` (480x300, фокус у игры). Владелец за ПК: предупредить. Владелец не за ПК: окна закрываю сам.
- Запуск только через `_run_when_free.ps1` или `_smoke_click.ps1`; закрытие `_close2.ps1` (Alt+F4, X, потом клик по «Выйти» в координатах 530,330 на снимке шириной 1280). Висит окно «Выход из игры»: снимок `tools\shotwin.ps1`, клик, не ждать.
- Скрипты PowerShell с кириллицей писать с BOM (`utf-8-sig`) и проверять разбор `castle-fight\_parsecheck.ps1`; без BOM PS 5.1 ломал кавычки (повторилось, хотя правило было).
- Мышь и клавиши в игре: `_smoke_click.ps1` (клики `-clicks "сек:x:y;..."` в системе снимка шириной 1280, клавиши `-keys "сек:b"`; меню строительства открывается клавишей `b`).
- Хуки проекта блокируют команды со словами про удаление (`Remove-Item`, шаблон `Rd` в grep): переименовать/перенести или другой путь.
- `printf` и heredoc с обратными слэшами портят пути в `state.md`: файлы состояния писать Write/Edit.

## 7. Уроки чата командиров 2026-11-20 (крит Юры, уклонение Леши, украинская кузница)
- **Единицы полей способностей проверять по игре, не по догадке.** Крит AIcs: `Ocr1` в ПРОЦЕНТАХ (25 = 25%), я записал 0.25 и получил 0 критов из 67 ударов. Уклонение AIev: `Eev1` долей (0.2 = 20%). Перед записью нового поля открыть `Units\AbilityData.slk` из `castle-fight\mpqcopy` (строка способности, колонка DataA1) и сверить масштаб.
- **«Способность висит на бойце» (лог ev=1, cr=1) не доказательство эффекта.** Новую способность шанса мерить в бою: `build_cf.py testc`, лог `M att= dmg= min= big=`, ожидаемую долю сравнивать с фактом (замер 2026-11-20: крит 23% при 25%, уклонение 23% при 20%).
- **Паузу в измерении не ставить на цель с уклонением:** PauseUnit отключает уклонение (2 промаха из 69). Цель держать на месте через `SetUnitMoveSpeed(u,0.)`.
- **Тексты кнопок с числами и украинская карта.** Если описание способности собирается в `build_cf.py` из чисел (кузница Cf01-Cf03), точной строки в таблице перевода нет, подмена по точному совпадению его пропускает, и кнопка выходит с украинским заголовком и русским описанием. Любые такие тексты переводить шаблоном в `build_ua.py` (список `FORGE_PH`), а после каждой смены текстов прогонять `python -X utf8 tasks\2026-11-18-cf-ukr\_scan_ru_left.py <украинская карта>`; в игроцких строках не должно остаться русских букв ы э ъ ё.
- **Многострочные литералы оригинала** (приветствие, «не выходите из игры») построчная подмена перевода не видит: переводятся точечной заменой фрагмента в `build_ua.py`.
- **Цена на кнопке одна на всех игроков**, индивидуальную скидку командира в заголовке не показать. Показываем в подсказке («Командир Алик (-50%): X») и в сообщении при покупке «цена N, заплачено M».
- **Сборка украинской карты при запущенной игре:** `CF_MPQDIR="...\castle-fight\mpqcopy" python -X utf8 build_ua.py 28_ua`, иначе StormLib не открывает MPQ игры (код 32).
- **Перед пересборкой той же версии** старый файл перенести в `Maps\_old_tests\cf` (или `cf_ua`) с суффиксом (`_pre-critfix`), не затирать.
- **Баланс командиров:** считать в золото-эквиваленте по `_econ.py` (раунд 15 мин), цель +22-24% силы армии. Расчёт 2026-11-20: Саша +20% дохода давал +38%, Алик -30% на кузницу +13%; выровнено до Саша +12%, Алик -50%, Дима и Дэн +24%, Юра крит 25% x2, Леша уклонение 20%. Простая модель «копить на кузницу вместо зданий» даёт обвал и не годится, считать окупаемость уровня по средней армии до конца раунда (`_econ2.py`).
- **Запуск теста:** `war3` занят соседним чатом -> `_run_when_free.ps1 ... -maxWait 570` и `run_in_background` (вывод `timeout: war3 still busy` значит, что тест не стартовал, лог старый). Если скрипт вывел `running`, а в логе уже FINISH, игру закрыть `_close.ps1`.
